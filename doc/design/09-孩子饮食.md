# 09 · 孩子饮食

2026-10-18。孩子每天吃什么：爸爸妈妈排计划，奶奶照着做、喂完记一下，两边对照着看。

## 1. 两张表（迁移 0018）

| 表 | 是什么 | 谁能写 |
|---|---|---|
| `pa_diet_plan` | 预先计划：哪天哪一餐打算吃什么、有什么要求。`meal=day` 是这一天的总体要求（一天一杯奶、不给糖） | 我（admin / member）和老婆（spouse）；奶奶（elder）只看 |
| `pa_diet_record` | 实际发生：什么时候、哪一餐、吃了什么、吃了多少（all / most / half / little / none）、情况、照片 | 所有角色，能记、能改、能删 |

- 餐次：早饭、上午加餐、午饭、下午加餐、晚饭、睡前（`service/diet.Meals`），没说哪一餐按时间猜。
- 孩子用 `child_key`（pa_person），默认 `daughter`，以后有第二个孩子不用改表。
- 全家共用，不走 08 的可见范围（不是受保护的表）。删除是软删（status=deleted），`created_by` / `updated_by` 记账号。
- 权限在服务端判断（`diet.Actor.CanPlan`），不只靠前端隐藏。

## 2. 两边都交给大模型

两边都可以说一句话（语音先转文字）或者拍照，交给模型整理，直接生效，不用再确认；整理错了在页面上点一下改。

**实际（`POST /diet/records/capture`，路由 `diet.extract`）** —— 奶奶主要的记法：
- 照片先存（`diet/{family}/{capture}/N.jpg`），再把照片、原话、当天的计划、当天已经记过的一起给模型；
- 模型输出一餐一条（餐次、时间、吃了什么、吃了多少、情况）；说的是打算不是已经吃了的不记；
- 「按计划吃的」会填成计划的内容；
- 模型不可用 / 没整理出来时，**原话照样记一条**（fallback），不丢；
- 回一句「记好了。午饭：……，吃了一半。」由代码按记下的内容拼（长辈模式会读出来），不让模型自由发挥。

**计划（`POST /diet/plans/capture`，路由 `diet.plan`）** —— 我和老婆用：
- 「下周每天早上一个鸡蛋，周三晚饭吃鱼」「按她最近吃的排一下下周」「（拍幼儿园食谱）」；
- 给模型：今天、正在看的日子、已有计划（多给一周）、最近 14 天实际吃了什么、孩子年龄；
- 模型只输出要改的餐（改完后的完整内容，或 clear 取消），过去的日子不改；
- 手动改单餐（`PUT /diet/plans`）、把上周计划抄到这周（`POST /diet/plans/copy`）也保留。

两个路由迁移时复制 `memory.extract` 的模型（要能看图、会输出 JSON），没有就不写，需要到管理端「模型路由」补上。

## 3. 入口

- 我 / 老婆：对话首页快捷入口「宝宝吃饭」→ `/diet`：一周日期条，每天按餐把「计划 / 实际」上下对照；底部输入框切「记实际 / 改计划」，可打字、说话、拍照。
- 奶奶：长辈模式首页第四张大卡「宝宝吃饭」→ `/elder/diet`：上面是今天排的（标出「下一顿」，可以点喇叭读出来），下面是今天已经记的；底部「拍照 / 按住 说话 / 打字」，说完就记，回话读出来。

## 4. 对话里能查（迁移 0019）

- 新工具 `diet_overview`（from / days / child）：按天、按餐列出计划和实际（`diet.Summary`）。私人助理、万能通、女儿档案默认带上，迁移给已有的这三个机器人补上。
- 「这周她吃得怎么样」「有没有按计划吃」「最近青菜吃了吗」都能答。

## 5. 每周对照（迁移 0019，路由 `diet.review`）

- 表 `pa_diet_review`：每个孩子每周一条（周一为准），唯一键 (family, child, week_start)。
- 周日晚上 8 点后自动生成这一周的：把这周每天的计划 / 实际、下周已排的计划、孩子年龄交给模型，写一段对照（总体 → 吃得好的 / 没按计划的 / 计划本身的问题 → 下周 1-3 条建议）。这周记录少于 3 条就不写。
- 语气就事论事，**不评价喂饭的人**（不写「奶奶没有……」），记录不全时注明仅供参考。
- 推送：给每个能改计划的账号（我、老婆，`identity.PlanAccounts`）各建一条只提醒自己的提醒，点开到 `/diet`。奶奶不推。
- 先占位再生成，两个进程只有一个跑；生成失败会删掉占位，15 分钟后再试。
- 页面 `/diet` 底部「这周对照」卡片：看当前这周的，爸爸妈妈可以「现在对照一下 / 重新对照」（`POST /diet/review`，覆盖）。

## 6. 问「明天该吃什么」（2026-10-19，迁移 0020）

万能通里可以直接问「小朋友明天该吃什么」「今晚给她做点啥」，它会把计划和实际放在一起出主意。

- `diet_overview` 加参数 `for_date`（`diet.AdviceContext`）：一次给出孩子年龄、今天到那天已经排的计划、最近 14 天（含今天）的计划和实际、最近一次每周对照（这周没有就用上周的）。只给事实，建议由对话模型写。
- 万能通提示词加第 5 条：先 `diet_overview(for_date)`，再 `search_memory` 查过敏、不爱吃、最近不舒服；排了计划的餐照计划说，按最近实际补一句怎么调；没排的餐给具体的菜和理由；一餐一行，标「计划 / 建议」；不评价喂饭的人。万能通别的事仍然不出主意。
- 建议不写进计划，要排进去去「宝宝吃饭」页面改。
- 迁移 0020 只替换出厂提示词的最后一段，管理端改过这一段的不动（可以「恢复默认」）。提示词在会话开始时冻结，**新开对话才生效**；工具列表不冻结（见 02 · 3），工具说明里写了 `for_date`，所以开着的私人助理、女儿档案对话部署后也能这样查。

## 7. 管理端「宝宝饮食」（2026-10-19）

管理端左侧「家庭 → 宝宝饮食」（`/diet`），接口和 App 端一样挂在管理端 `/api/diet/*`（`manager-api/pkg/diet`，调同一个 `service/diet`）。管理端账号是我（admin / member），能改计划。

- **一周对照**：行是全天要求 + 六餐，列是周一到周日；格子上面是计划（黄色虚线框），下面是实际（绿色，带时间、吃了多少的小刻度、照片数，模型整理的带 ✦）。过去的日子排了计划没记录的，计划框打斜线。今天那一列高亮。
- **点格子编辑**：抽屉里改这一餐的计划（保存 / 取消计划）；看这一餐的实际记录（原话、照片、谁记的谁改的），可以改时间、餐次、日期、吃了什么、吃了多少、情况，删除，或者补一条。
- **说一句让模型改**：右侧对话框切「改计划 / 记实际」，打字、说话（`/speech/transcribe`）、附照片（最多 4 张），走 `POST /diet/plans/capture`（from = 正在看的那周的周一，days = 7）和 `POST /diet/records/capture`，直接生效；回复里列出改了 / 记了哪几餐，周视图里对应格子闪一下。
- **可视化**：顶部 4 个数（这周计划的餐、实际记录、计划的餐有记录的比例（只算到今天）、吃完 / 吃了大半的比例）；「每天吃了多少」柱状图：虚线框是计划了几餐，实心柱是记了几条，按吃了多少分段，悬停看明细。
- 底部「这周对照」：看 / 重新生成每周对照（同 §5）。
- 周切换（上一周 / 下一周 / 选周 / 回到本周）、「抄上周计划」（覆盖这周已有的餐）；家里有不止一个孩子（有生日且不到 16 岁）时右上角可以切换。
