# 10 · 宝宝穿衣

2026-10-20。每天早、中、晚各推一次：按实时天气和接下来几小时的预报，告诉带孩子的人宝宝该穿什么、几点出门、最晚几点到家。天太冷、要下雨、风大、空气差时，提醒接到就直接回、早点回来。

这一篇只是设计，还没写代码。2026-10-20 已和我确认：天气用百度搜到的那份（中国天气网，不用 key）、默认上海青浦、平时送接时间、推给我和奶奶、回家线。

## 1. 一句话流程

```
定时（早 / 中 / 晚）
  → 天气模块取「实况 + 逐小时 + 按天（含日出日落）+ 预警 + 生活指数」（带缓存）
  → 取这一天的送接安排（默认 + 当天临时改的）
  → 规则算出：穿几层、穿什么、要带什么、几点出发、最晚几点到家、原因（结构化，不经过模型）
  → 模型把结构化结果写成两三句家常话（失败就用模板拼）
  → 存 pa_weather_brief（一天一个时段一条）
  → 推给我和奶奶（长辈模式读出来）
```

**原则：数字和时间由代码算，模型只负责说人话。** 和饮食的「回一句由代码拼」一样——几度、穿几层、几点前到家不能让模型自由发挥。模型写的话里出现的温度、钟点必须和规则算出来的一致，对不上就用模板。

## 2. 天气模块（新，`service/weather`）

单独一个模块，以后别的功能（回老家、对话里问天气）也能用。

### 2.1 数据源：中国天气网（就是百度搜「青浦天气」那张卡片的数据），不用 key

本来想直接抓百度搜索结果，试了：服务器上请求百度搜索第一次就跳「安全验证」（图形验证码），抓不了，也不该去绕。百度天气卡片的数据来自中国天气网，它的页面数据接口直接能取，**不用注册、不用 key**，2026-10-20 实测青浦都能拿到：

| 地址（`http://d1.weather.com.cn/…`，请求带 `Referer: http://www.weather.com.cn/`） | 拿到什么 | 用在哪 |
|---|---|---|
| `sk_2d/{code}.html` | 实况：温度、湿度、风向风力、天气、1 小时 / 24 小时降水、AQI、PM2.5、更新时间 | 现在穿什么、空气 |
| `wap_180h/{code}.html` | 逐小时预报：天气、温度、风、湿度、降水量 | 送接时段的体感、几点开始下雨、最晚到家 |
| `wap_40d/{code}.html` | 按天：最高最低、天气、**日出日落** | 早晚温差、天黑时间、明天预告 |
| `dingzhi/{code}.html` | 今天白天 / 夜里概况 + **预警**（`alarmDZ`） | 寒潮、大风、暴雨、高温 → 第一句就说 |
| `weather_index/{code}.html` | 生活指数，含**穿衣指数**、感冒指数 | 附上作参考，不作为判断依据 |

要注意的：
- 这些是网页自己用的数据接口，**没有公开文档、字段是缩写**（比如逐小时里 `jb`=温度、`jf`=时间、`jg`=降水量），以后可能改版。解析写得宽松：哪个字段解析不出就当没有，整份解析失败就换备用源；每次解析失败记日志，管理端「天气接口状态」能看到。
- 返回的是 `var xxx = {...}` 形式的 JS，去掉前缀按 JSON 解析；要带 Referer 和普通浏览器 UA。
- 实况里没有体感温度，**体感由代码算**：按温度、湿度、风速（冷天用风寒公式，热天用体感热指数），和预报的体感口径一致。
- 请求要克制：整份缓存 20 分钟，一天几十次，不会给对方添麻烦。

**备用：Open-Meteo**（`api.open-meteo.com`，同样不用 key，返回正规 JSON，有逐小时体感温度和降水概率；没有预警和穿衣指数）。中国天气网取不到或解析失败时自动用它，推送里不区分。

做成 `Provider` 接口，以后要换别的源只加一个实现：

```go
type Provider interface {
    Fetch(ctx context.Context, loc Location) (Snapshot, error) // 实况 + 逐小时 + 按天 + 预警 + 指数
}
```

- **缓存**：整份快照缓存 20 分钟，存 Redis（`pa:weather:{provider}:{code}`）；Redis 不可用就用进程内缓存。
- **失败**：两个源都取不到就用缓存里最近一次（推送里写「X 点的数据」）；超过 3 小时的不用，推送改成「天气暂时查不到，出门前看一眼窗外」，不瞎编。

### 2.2 位置（可配置，默认上海青浦）

配置在 `pa_setting` 组 `weather` 的 `location`：

```json
{"name": "上海 青浦", "code": "101020800", "lat": 31.151, "lon": 121.124}
```

- `code` 是中国天气网的城市编码（青浦 101020800），`lat` / `lon` 给备用的 Open-Meteo 用。
- 管理端「宝宝穿衣 → 设置」里搜位置：输「青浦」「赵巷」→ 调中国天气网的城市搜索（`toy1.weather.com.cn/search?cityname=…`，实测能搜到镇一级，比如赵巷镇 101020800009）→ 选中填好编码；经纬度按区县内置一张表，查不到就手填。
- 回老家时改成老家的地方，推送就按那边的天气；App 的 `/weather` 页上也能切「宝宝现在在哪」（我能改，奶奶只看）。
- 以后可以接行程（`trip`）：行程期间自动切，见 §8。

### 2.3 对外

- `weather.Service.Snapshot(ctx) (Snapshot, error)`：给穿衣、对话工具、页面用。
- 对话工具 `weather_now`（hours / place）：私人助理、万能通、提醒机器人带上，「现在外面冷不冷」「下午会不会下雨」能答。

## 3. 送接安排（灵活，不是一成不变）

默认（`pa_setting` → `weather.schedule`，管理端改）：

| | 时间 | 说明 |
|---|---|---|
| 工作日 · 送 | 08:00 出门 | 送幼儿园 |
| 工作日 · 接 | 15:50 接 | 接幼儿园 |
| 工作日 · 到家 | 16:30 前 | 平常到家时间（接完可能在外面玩一会） |
| 周末 | 上午 09:30–11:00、下午 15:00–16:30 | 出去玩；可以关掉 |

**当天临时改**（表 `pa_weather_day`，一天一条覆盖默认）：

- 「今天不去幼儿园」「今天 4 点 10 分接」「今天下午去外婆家，6 点回」「明天放假」——在 `/weather` 页点一下改，或者跟提醒机器人 / 万能通说一句（工具 `set_outing`，只改这一天，不动默认）。
- 奶奶也能改当天的（她最清楚今天怎么安排），改完下一次提醒就按新的算。
- 法定节假日：先不接节假日接口，放假那几天手动标「不去幼儿园」；周末按周末的默认。

## 4. 穿衣规则（`service/weather/outfit.go`，纯函数，好测）

输入：天气快照、孩子年龄（`pa_person.birthday`）、当天送接安排、时段、配置的阈值。输出：

```go
type Advice struct {
    FeelsLike  int        // 用来判断的体感：取要在外面那段时间里最低的
    Level      string     // hot / warm / mild / cool / cold / freezing
    Layers     int
    Clothes    []string   // 短袖、薄外套、毛衣、羽绒服、帽子……
    Extras     []string   // 雨具、防晒帽、口罩、围巾手套、书包里备一件
    Leave      *time.Time // 几点出发（送 / 出去玩）
    BackBy     *time.Time // 最晚几点到家
    BackReason string     // 「4 点以后降到 8 度」「4 点左右开始下雨」「5:10 天黑」
    PlayUntil  *time.Time // 天气好时：接完可以在外面玩到几点
    Stay       bool       // 别在外面玩 / 少出门（预警、空气重度污染、极冷极热）
    Notes      []string   // 早晚温差大、风大、夜里冷注意盖被子……
}
```

### 4.1 穿几层（按体感，管理端可调）

| 体感 | 档 | 建议 |
|---|---|---|
| ≥ 28 | hot | 短袖短裤，透气；避开中午暴晒，带水 |
| 23–27 | warm | 短袖或薄长袖；早晚带件薄外套 |
| 18–22 | mild | 长袖 + 薄外套 |
| 13–17 | cool | 长袖 + 卫衣 / 薄毛衣 + 外套 |
| 8–12 | cold | 秋衣秋裤 + 毛衣 + 厚外套，戴帽子 |
| 3–7 | cold | 保暖内衣 + 毛衣 + 羽绒服，帽子、围巾 |
| < 3 | freezing | 羽绒服 + 帽子手套围巾；在外面尽量短 |

调整：
- **幼儿园一整天**：早上送的时候冷、中午热（温差 ≥ 8 度）→ 「穿能脱的，外套进教室脱」；冷天书包里备一件，出汗湿了能换。
- **年龄**：1 岁以内比上表多一层；会跑会跳的在外面玩不用多穿。都加一句「摸后颈，温热不出汗就合适」。
- **风**：≥ 4 级，体感再降 2 度，提醒挡风外套；≥ 6 级标「风大」。
- **雨**：要在外面的时段里逐小时有雨 → 雨具、防水鞋；正在下 → 接到直接回。
- **空气**：AQI > 150 戴口罩、别在外面玩；> 200 尽量别出门。
- **预警**：寒潮、大风、暴雨、高温、雷电等黄色及以上 → `Stay=true`，第一句就说。

### 4.2 最晚到家

工作日下午（默认 15:50 接、16:30 前到家）：

1. 先按逐小时预报算「该回家的时刻」= 下面几个里最早的：
   - 体感降到**回家线**以下（10 度；1 岁以内 12 度）；
   - 开始下雨 / 下雪的那个小时，提前半小时；
   - 日落后 30 分钟。
2. 和平常到家时间（16:30）比：
   - 更早 → **「接到直接回，X 点前到家」**，推送标题就写这个；太冷（`cold` 档以下）或者有雨、预警，不管算出几点，都是「接到直接回」。
   - 更晚、天气好 → 照常 16:30；在 `PlayUntil` 里写「天气好，想多玩一会可以到 X 点」（不超过日落、不超过回家线）。
3. 越冷在外面越短：`cold` 档在外面不超过 1.5 小时，`freezing` 不超过 40 分钟；`hot` 档提醒在阴凉处、多喝水。

早上送（08:00）：不改送的时间，只管穿什么、带什么；有暴雨、大风预警时提醒「路上注意 / 要不要开车送」。

周末出去玩：按配置的时段算建议出门窗口（冷天往最暖的时候挪，比如冬天改成 14:00–15:30），回家时间同上。

当天临时改了时间的，就按改后的时间算。

## 5. 每天三次

| 时段 | 默认时间 | 说什么 |
|---|---|---|
| 早 | 07:00 | 送幼儿园穿什么、带什么；今天最高最低、有没有雨和预警；中午热不热、外套要不要脱 |
| 中 | 12:00 | 下午 3:50 接：穿什么、带什么；**几点前到家 / 接到直接回**；天气和早上预报不一样要说（「早上说不下雨，现在 4 点后有雨」） |
| 晚 | 18:30 | 夜里最低多少、睡觉盖什么、空调 / 暖气要不要开；**明早送的时候多少度、穿什么**，好提前把衣服准备好 |

- 时间、开关都能在管理端改（`pa_setting` → `weather.slots`）。
- **接之前再看一眼**：15:20（接前半小时）重新算一次，和中午的结论比——到家时间提前了 30 分钟以上、新出了雨或预警、体感比中午预报低 3 度以上，就补推一条「临时提醒」；没变化不推。
- 天气突变（新的黄色以上预警）不等定时，立刻推一次。临时提醒一天最多 2 条。
- 不去幼儿园的日子（周末、临时标了放假）：早上那条改成「今天在家 / 出去玩」的版本，中午那条按出去玩的时段算；没安排出门就只说穿什么。

### 5.1 生成和推送

- 表 `pa_weather_brief`：每个孩子每天每个时段一条，唯一键 (family, child, date, slot)。和饮食点评一样**先占位再生成**，两个进程只有一个跑；失败删占位，5 分钟后再试，过了这个时段 1 小时就不补。
- 生成：`Advice` + 天气快照摘要 → 路由 `weather.brief`（迁移复制 `chat.assistant` 的模型，没有就只用模板）→ 两三句话，开头一句结论（「今天冷，接到直接回，4:10 前到家」），后面穿什么。
- 校验：模型话里的温度、钟点必须在 `Advice` / 快照里出现过，否则丢掉用模板（`source=template`）。
- **推给我和奶奶**：配置 `recipients` 默认 `["admin", "member", "elder"]`（按角色）——就是我（admin）和奶奶（elder）的账号；老婆（spouse）默认不推，以后要推在管理端勾上。每人各建一条只提醒自己的提醒（`reminder.CreateManual`，私有），点开到 `/weather`（奶奶到 `/elder/weather`）。
- 现在家里只有我一个 App 账号；奶奶的账号建好、在她手机上打开过推送以后才收得到。管理端「推送状态」能看到每次推给了谁、成没成功。
- 推送标题：「👕 宝宝穿衣 · 早上」/「🧥 今天冷，接到直接回，4:10 前到家」，正文两三句。长辈模式打开时自动读出来（已有 TTS）。

## 6. 表和配置（迁移 0021）

```sql
CREATE TABLE pa_weather_brief (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  brief_key   VARCHAR(40) NOT NULL,
  family_key  VARCHAR(40) NOT NULL,
  child_key   VARCHAR(40) NOT NULL,
  place_code  VARCHAR(16) NOT NULL COMMENT '当时按哪里的天气（中国天气网编码）',
  brief_date  DATE        NOT NULL,
  slot        VARCHAR(16) NOT NULL COMMENT 'morning / noon / evening / alert1 / alert2',
  snapshot    JSON        NULL COMMENT '当时用的天气（实况 + 逐小时摘要 + 预警）',
  advice      JSON        NULL COMMENT '规则算出来的 Advice',
  content     TEXT        NULL COMMENT '推送正文；空 = 正在生成或失败',
  source      VARCHAR(16) NOT NULL DEFAULT 'llm' COMMENT 'llm / template',
  pushed_to   JSON        NULL COMMENT '推给了哪些账号',
  created_by  VARCHAR(40) NOT NULL DEFAULT '' COMMENT '手动生成的账号；定时为空',
  created_at  DATETIME NOT NULL, updated_at DATETIME NOT NULL,
  UNIQUE KEY uk_weather_brief_key (brief_key),
  UNIQUE KEY uk_weather_brief_slot (family_key, child_key, brief_date, slot)
);

CREATE TABLE pa_weather_day (            -- 当天送接临时改
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  family_key  VARCHAR(40) NOT NULL,
  child_key   VARCHAR(40) NOT NULL,
  day         DATE        NOT NULL,
  no_school   TINYINT     NOT NULL DEFAULT 0,
  outings     JSON        NULL COMMENT '[{"kind":"drop|pickup|play","at":"16:10","backBy":"17:00","note":"去外婆家"}]',
  updated_by  VARCHAR(40) NOT NULL,
  created_at  DATETIME NOT NULL, updated_at DATETIME NOT NULL,
  UNIQUE KEY uk_weather_day (family_key, child_key, day)
);

-- 路由 weather.brief 复制 chat.assistant
-- 助理 / 万能通 / 提醒机器人补上 weather_now、set_outing 工具
```

## 7. 界面

### App（`client/app`）

- **首页卡片**（我）：「14° 多云 · 毛衣 + 外套 · 接到直接回，4:10 前到家」，点开到 `/weather`。
- **`/weather` 页**：
  - 顶部：现在几度、体感、天气、风、空气；位置（可切换）。
  - 「今天穿什么」：几层、衣服图标、要带的。
  - 时间条：今天逐小时温度曲线，标出送（8:00）、接（3:50）、「最晚到家」竖线、天黑时间，雨的时段打阴影。
  - 「今天的安排」：默认的送接时间，点一下改今天的（不去 / 改接的时间 / 加一段出去玩）。
  - 今天的提醒（早 / 中 / 临时 / 晚）原文，没到时间的灰着；「现在再算一下」（不推送）。
  - 明天预告。
- **长辈模式**：首页加一张大卡「宝宝穿什么」→ `/elder/weather`：大字一句结论 + 衣服大图标 + 超大字「4:10 前到家」，喇叭读出来；下面一个大按钮「今天安排变了」→ 按住说话（「今天 4 点半接」）→ 走 `set_outing`。

### 管理端（`client/manager`）

左侧「家庭 → 宝宝穿衣」（`/weather`），接口挂 `/api/weather/*`（`manager-api/pkg/weather`，调同一个 `service/weather`）：

- **今天**：实况 + 逐小时图；每条提醒的内容、规则算的结果（档位、几层、到家时间和原因）、模型写的还是模板、推给了谁、推送成功没。
- **试一下**：选时段、日期（今天 / 明天）→ 预览，不推；确认后「现在推送」。
- **安排**：默认送接时间、周末时段；这周每天的临时改动一览。
- **设置**：位置（搜区县）、推送时间、回家线、穿衣档位表、推给谁、临时提醒开关。
- **天气接口状态**：当前用的哪个源（中国天气网 / 备用 Open-Meteo）、最近一次成功时间、今天调用次数、最近的解析错误（对方改版时第一时间能看到）。

## 10. 实现说明（2026-10-21）

| 地方 | 文件 |

和上面设计不一样的地方：

- **缓存不用 Redis**：项目里没有 Redis 客户端，先放进程内（20 分钟）。两个进程各取各的，一天也就几十次。
- **体感公式**：26 度以上用 Steadman（算湿度）；26 度以下只算风（每超过 1.5 m/s 冷 0.7 度），10 度以下又潮再冷 1 度。上海潮，凉快天也算湿度会把 25 度算成 29 度、穿少了。风已经算进体感，规则里不再额外减。
- **「直接回」看接的那一刻**：接的时候体感已经低于回家线才「接到直接回」；之后才降下来的，按降下来的时刻定几点到家。
- **临时提醒只看预警**：新出现的黄色以上预警立刻推；「比预报低 5 度」先不做，靠接之前那次（15:20）再看一眼兜住。
- **长辈模式改安排用按钮**（去 / 不去、几点接的大按钮），不在这个页面上说话；要说话就去「提醒」「万事通」说。
- **换地方**：App 上只有我能切（奶奶、老婆的账号看不到这个按钮，接口也拒绝）。
- 推送进提醒表的 `kind = weather`，提醒列表里显示「穿衣」。
