# 08 · 角色与可见范围

2026-10-18。接 01 · 8.1「老婆知情，未来可能一起用」：家里每个人用自己的账号，看到的界面不一样，记下的东西默认只有自己看得到。

## 1. 角色（pa_account.role，手机端）

| 角色 | 谁 | 界面 | 能用的机器人 |
|---|---|---|---|
| admin / member | 我自己 | 原来的全部功能，不变 | 全部 |
| spouse | 老婆 | 对话、速记、今天；没有「家人」页和人设变化 | 万能通、提醒 |
| elder | 奶奶 | 长辈模式 `/elder`：大字、按住说话、回答朗读，只有万事通 / 记一下 / 提醒 | 万能通、提醒 |

- 机器人白名单在服务端 `service/identity/role.go`（`BotAllowed`），`/bots` 和新建对话都检查，不只靠前端隐藏。
- 角色在管理端「账号」页设置；前端按 `/auth/me` 的 role 进对应界面（`client/app/src/lib/role.ts`）。

## 2. 可见范围

记忆（pa_memory）、原始记录（pa_source_note）、提醒（pa_reminder）各加两列（迁移 0017）：

- `owner_account`：谁记的 / 谁设的；
- `visibility`：`private` 只有他自己看得到，`family` 全家都看得到。

规则：

- **新记录默认 private。** 我自己（和老婆）的账号在速记页可以展开「谁能看到」改成全家；记忆、提醒详情里自己的那条也能随时切换。对话里明确说「让全家都知道」「提醒全家」，模型会在 remember / create_reminder 里传 `visibility=family`。
- **奶奶的账号锁定为 private**，不显示选项，服务端也强制（`viewer.Resolve`）。
- 查询一律只返回「全家可见的 + 自己的」。改可见范围只有归属人自己能改。
- 已有数据迁移时归到第一个手机端管理员账号（我）名下，设为 private——老婆、奶奶登录看不到我以前记的东西。

### 实现：在数据访问层强制（common/viewer）

隔离不靠每个查询自己记得加条件，而是在数据访问层统一强制。`wire.Build` 给数据库连接装上 `viewer.Plugin`（gorm 插件），只要语句碰到 pa_memory、pa_source_note、pa_reminder 这三张表，规则如下：

| 语句 | 插件做什么 |
|---|---|
| 查询、计数、Pluck、更新、删除 | 自动加上 `` (`表`.`visibility` = 'family' OR `表`.`owner_account` IN (当前账号)) `` |
| 新建 | 逐行检查：只能写当前身份看得到的行，不能替别人写私有记录 |
| Joins 连到这三张表 | 插件没法替别名加条件，要求调用方用 `viewer.Clause(ctx, "m.")` 自己加，没加直接报错 |
| 手写 SQL（Raw / Exec）提到这三张表 | 同上，必须自带 `viewer.Clause` 拼出的条件 |
| context 里没有声明身份 | 以上全部直接报错（`ErrNoIdentity`），不会默认放行 |

所以业务代码直接写 `s.db.WithContext(ctx)` 即可，写漏了条件也查不到别人的私有记录；忘了声明身份的新入口会报错，而不是悄悄多给数据。

**身份必须显式声明，只有三种：**

- `viewer.With`：登录账号。app-api 在登录校验后放进请求 context（`router.go` 的 `withViewer`），奶奶的账号带 `Locked`。
- `viewer.AsSystem`：系统账号，即家里 role 为 admin/member 的手机端账号（`identity.SystemAccounts`，wire 注入），看得到我的私有记录，看不到奶奶的。管理端所有请求、人设卡、周洞察、对话学习、启动时写默认数据用它。
- `viewer.Unscoped`：不过滤。领取待整理的原始记录、提醒调度和推送、补算向量、评测用它。

后声明的覆盖先声明的。比如整理原始记录时，后台先用 Unscoped 领取，再以记录主人的身份（`With`）查重、建记忆，新记忆继承记录的归属和可见范围；派生提醒同步不管谁触发都切到 `AsSystem`。

其它要点：

- 向量召回先按可见编号过滤再取 Top K（`visibleKeys` / `visibleNotes`），否则奶奶记忆少，Top K 可能被别人的私有记忆占满。原文片段、记忆向量补算时用 Unscoped，检索时再过滤。
- 没有归属账号（还没建手机端账号、评测库）时新记录只能全家可见，否则谁也看不到。
- 插件的规则有单元测试（`common/viewer/gorm_test.go`，用 gorm 的 DryRun 检查生成的 SQL 和拒绝）。

**这仍然是应用层的隔离**：用数据库账号直接连库查表，还是能看到全部数据。要在数据库层面隔离，得换成「视图 + 只能访问视图的受限账号」或分库，见第 3 节。

### 推送

- private 的提醒只推给归属账号订阅的设备；family 的推给全家所有设备。
- 生日、节日、日报这些派生提醒归系统账号、private：只推给我。
- 测试推送只发给点按钮的人自己的设备。

### 提示词里的「我的整理」

人设卡、关系要点、人物概况是从我的私有记忆整理出来的。老婆、奶奶的账号（`viewer.IsSystem` 为假）对话时：系统提示词里不放人设卡和关系要点，不提示人设卡更新，get_person 只给称呼、生日、住哪和她看得到的记忆。

## 3. 还没做

- **说话人**：机器人提示词都假设说话的是我。奶奶说「我的眼镜」「提醒我」，记忆的主体、提醒的称呼还是按我理解。归属和可见范围已经对了，内容上的「我」还没按账号对应的家人换。
- 管理端看到的是系统账号的视角（我的 + 全家的），看不到奶奶的私有记录；管理端还不能改可见范围。
- 「全家可见」是全家所有账号，还不能只给某一个人看。
- 对话（pa_conversation / pa_message）App 端按账号分开，但管理端的「对话」页仍能看到所有账号的对话，包括奶奶的。
- 隔离在应用的数据访问层，数据库账号直接查表不受限。要更进一步：手机端请求改用只能访问视图的 MySQL 账号（视图按连接上的登录账号过滤、写入用 WITH CHECK OPTION），需要在 RDS 上新建账号。
