# M4（主动提醒）实现说明

> 日期：2026-10-07 · 承接 [03-M2M3实现说明.md](03-M2M3实现说明.md)

## 1. 提醒来源

- 人物生日：公历/农历均支持，农历用 `lunar-go` 按当年换算；提前 7 天和当天提醒。
- 承诺与带日期的事：读取记忆 `attrs.dueAt`，提前 1 天和当天提醒；标记 `done/addressed` 或记忆失效后自动取消未发送提醒。
- 传统节日：春节提前 14 天，端午/中秋提前 7 天。
- 每日简报：每天 08:00，统计未完成承诺/诉求与 7 天内到期数。
- 手工提醒：助理通过 `create_reminder` 工具建立；`list_upcoming` 可查近期提醒。
- 回老家行程：出发前 2 天推送简报。

所有自动派生都有 `dedupe_key`，两个 API 进程重复扫描也不会重复建提醒。到期投递使用 MySQL `GET_LOCK`，没有引入 Redis。

## 2. 回老家简报

手机端「今天 → +回老家行程」建行程。简报实时根据结构化数据组装：

1. 目的地常住人和手工指定的人；
2. 我该怎么称呼、关系要点和雷区；
3. 地点档案里的规矩、行前准备；
4. 老婆与该地点直接相关的原话、矛盾、雷区和诉求（带记忆编号）；
5. 这次行程的手工备注。

简报不调模型，保证没有 Claude 也能按时生成，并且不会编造亲戚信息。

## 3. Web Push

链路：`pa_reminder` 到期抢占 → VAPID 加密 Web Push → Service Worker 显示通知 → 点击打开提醒或行程简报。

新增配置（两个 API 服务必须一致）：

```properties
push.vapid_public_key=
push.vapid_private_key=
push.vapid_subject=mailto:you@example.com
```

密钥只生成一次，后续更换会使现有设备订阅失效。iPhone 需要 iOS 16.4+、HTTPS，并且先用 Safari 「添加到主屏幕」；通知授权只在用户点「开启」时请求。

投递记录在管理端「提醒」页查看。HTTP 404/410 的过期订阅会自动停用，其他错误最多重试 5 次。

## 4. 数据表

- `pa_reminder`：提醒本体、派生源、去重键、投递状态。
- `pa_trip`：回老家行程。
- `pa_push_subscription`：按账号/设备保存的 Push API 订阅。
- `pa_push_delivery`：每个设备的投递结果。

## 5. 验证边界

已有农历转换、跨年、闰月格式、完成承诺不再提醒和 Push Topic 的单元测试。代码层可以在未配 VAPID 时运行，只是不投递。

仍需在真实 MySQL、HTTPS 域名和 iPhone 主屏 PWA 上完成最后联调。
