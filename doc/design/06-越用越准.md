## 1. 对话规则（可配置）

`pa_setting` 一行一个分组，值是 JSON，管理端「对话规则」页编辑，改完 30 秒内生效，「恢复默认」回到代码里的出厂值。

| 分组 | 内容 |
|---|---|
| `safety` | 危机词、排除短语（如「想死你了」「笑死」）、求助词、提示卡文案 |
| `budget` | 每轮检索条数和字数、工具结果字数、寒暄词、分段阈值 |
| `learning` | 对话自动抽取记忆（开关、空闲多久后抽取）、人设卡刷新的等待时间 |

危机命中记录：管理端列出最近命中危机词的消息（命中了哪个词、模型有没有给求助建议、有没有补卡），可以一键把误报的短语加进排除词。

## 2. 人设随对话演化

```
对话 ──空闲 N 分钟──▶ 原始记录（channel=chat，只取我说的话）
                        │ 现有抽取管线：去重、冲突进待确认
                        ▼
                      记忆 ──有新记忆、稳定 M 分钟──▶ 人设卡新版本（带变化说明）
                                                        │
进行中的对话 ◀── 每轮参考 <persona_update> ──────────────┘
```

- 对话里的原话不会被当场改写进系统提示词（只追加原则），而是在**下一轮的 `<turn_context>`** 里附上「人设卡 v3 → v4 的变化」；分身还会拿到新卡全文。
- 助理自己的话不抽取（它是建议，不是事实），只作为理解我原话的上下文。
- 每段对话记录抽取到了哪条消息，不会重复抽取。

实现要点：

- `service/chat/learner.go`：每分钟找空闲超过 N 分钟、有新消息的对话，整理成 `channel=chat` 的原始记录。只取我说的话；助理的话截 200 字作上下文；分身的回答整个不给。进度记在 `pa_conversation.extracted_message_id`。**迁移前已有的对话也会被整理一遍**（进度从 0 开始），整理出的记忆照常去重、冲突的进待确认。
- 人设卡每 10 分钟检查一次（原来 1 小时），记忆稳定 M 分钟后重写。
- `pa_conversation.persona_versions` 记会话已知的人设卡版本；有新版本时在下一轮 `<turn_context>` 里附 `<persona_update>`，提示一次后更新已知版本。迁移前开始的会话以当时的版本为基线，不补提示。

## 4. 按家里的记忆改写手册

管理端「做事手册 → 某本 → 按家里的记忆改写」：用手册的用途和正文检索相关记忆（最多 80 条，再补全家高重要度记忆），连同家庭档案、两边老家的规矩交给模型（路由 `skill.rewrite`），输出：

- 改写后的正文：结构和工具名不变，通用说法换成我们家的具体情况，每条具体内容标记忆编号；
- 改了什么、依据是什么；
- 记忆里还缺、建议补记的信息。

只是建议：点「采用」填进正文，核对后再保存（保存时版本 +1）。

## 5. 评测管理端里改过的版本

```bash
cd server/eval && go run . -from-source
```

`configs/application.properties` 里配 `source.sqlconn`（建议只读账号）。只复制 `pa_bot`、`pa_skill`、`pa_setting` 三张配置表；记忆和对话始终用 fixture 里的虚构数据，真实家庭数据不进评测库。报告开头写明评测的是哪份配置。

## 6. 分段阈值怎么调

每次分段记下：触发时上一轮的输入 token、摘要字数、**摘要漏掉的记忆**（助理在前一段回答里引用过、摘要里没有的编号）。管理端「对话规则 → 上下文预算」下面列出最近的分段；对话记录里分段那一轮也会标出漏了几条。

## 7. M5

| 功能 | 实现 | 管理端 |
|---|---|---|
| 话术示例 | 原设计的 Script 表并进手册：`pa_skill_example`。手机上点踩并写了「哪里不对」，后台用 `skill.example` 路由整理成一条**待审**示例，挂到最相关的手册下。审过的（每本最新 5 条）由 `load_skill` 拼在正文后面「我们家的示例」一节 | 做事手册 → 某本 → 我们家的示例：生效 / 不用 / 编辑 / 手工添加；卡片上显示待审数 |
| 周洞察 | `service/insight`：每周日 20 点后，把这周新记忆和没办完的承诺/诉求交给 `insight.weekly`，每个值得关注的人存一条 `insight` 类记忆（检索和人设卡都会用到），并建一条「本周回顾」提醒推送到手机 | 每周整理 → 周洞察，可「现在生成一次」 |
| 去重合并 | 同类型、同主体、向量相似度 ≥ 0.92 的生效记忆两两配对，写进 `pa_memory_merge` 待处理。保留一条，另一条**归档**（不删） | 每周整理 → 重复记忆：保留左边 / 保留右边 / 不是重复 |
| 批量导入 | 一大段导出的聊天记录按行切成每段约 6000 字，每段一条 `channel=import` 的原始记录，走现有抽取管线；一次最多 30 万字 | 原始记录 → 批量导入聊天记录（可选 txt 文件） |

每周任务用 `pa_job_run`（任务, 周, 家庭）做主键抢占，两个进程都跑也只执行一次；管理端手动触发不受限制。两项都能在「对话规则 → 自动学习」里关掉。找重复依赖向量化配置，没配会提示。

新增模型路由：`skill.rewrite`（Opus）、`skill.example`（Sonnet）、`insight.weekly`（Opus），都在「模型」里可改。

## 9. 手机上看人设变化

- 「今天」页：**她们最近的变化**——最近 7 天里生成的新版人设卡，一行一个人，显示变化说明，点进人物页（`GET /api/persona-changes?days=7`）。
- 人物页：**TA 的变化**——人设卡的全部版本时间线（第几版、哪天、变了什么、是否手工修订/回滚），默认显示最近 5 次（`GET /api/persons/:key/cards`）。
- 对话页：对话进行中某人的人设卡更新了，在这一轮我的话上方显示「老婆的人设有了新变化（第 5 版），这一轮已按新的理解来回答」，点开看变化说明并可跳到她的时间线。数据来自用户消息 `meta.personaUpdates`（现在带上了变化说明）。
