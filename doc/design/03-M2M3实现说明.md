# M2（自动记忆）+ M3（分身）实现说明

> 日期：2026-10-07 · 承接 [02-M1实现说明.md](02-M1实现说明.md)

## 1. M2：自动记忆

### 流程

```
手机「速记 → 整理聊天/截图」或管理端「原始记录 → 粘贴整理」
  → pa_source_note 原样落库（截图存 storage.dir），状态 queued
  → 后台 worker 领取 → 抽取（memory.extract 路由，结构化输出）
  → 每条候选检索相似旧记忆 → 有相似的才再调一次模型做比对
  → 写入：add / update（补充细节）/ supersede（她变了，进待确认）/ duplicate（已记过）
  → 结果摘要写回原始记录；手机「今天」页显示进度和结果
```

### 关键点
- **队列就是 `pa_source_note` 表**，按 `extract_status` 条件更新抢占，不依赖 Redis：进程重启不丢任务，两个 API 进程都跑 worker 也不会重复处理。失败自动重试 3 次（间隔 2 分钟），卡在 running 超过 10 分钟的会被重新领取。
- **抽取用结构化输出**（`output_config.format`），JSON 一定合法；schema 里每个对象都写了 `additionalProperties:false`，并有单元测试守着。OpenAI 兼容模型用 `json_object` 模式兜底。
- **没把握的进待确认**：置信度低于 `extract.auto_confirm`（默认 0.85）或要替代旧记忆的，进「今天」等确认。想全部人工确认就设成 1。
- **认不出的人**：抽取结果会列出来，提示去「家庭成员」添加（别名写原文里的叫法），然后点「重新整理」。重新整理不会重复记：比对环节会识别出已经记过的。
- **截图**：手机端上传前压成 JPEG（长边 1600px），顺带把 iPhone 的 HEIC 转成 JPEG；服务端按文件内容判断类型，只收 JPG/PNG/WebP/GIF，单张 5MB、一次 9 张以内。
- **离线速记**：「记一条」在断网时先存在手机本地，打开 App 或恢复联网时自动补交。

## 2. M3：分身

### 人设卡
- 表 `pa_persona_card`，按版本保存，同一个人只有一张 `active`。
- **自动刷新**：每小时检查一次核心成员（我除外）。有新的记忆变化、且最近一次变化已过去 20 分钟（等一批录完）才生成；至少 3 条记忆才生成。两个进程用 `GET_LOCK` 保证同一时刻只有一个在刷新。
- 生成时参考：当前有效的记忆 + 已过时的旧记忆（用来看出变化）+ 上一版人设卡。模型同时给出「这一版的变化」，没有实质变化就不新增版本。
- 成人和孩子用不同的小节结构（孩子侧重饮食、作息、健康、怎么哄）。
- 管理端「人设卡」：查看当前版本和历史、立即重新生成、手工修订（存为新版本）、回滚（把旧版本复制为新版本）。
- 手机端人物页顶部显示「TA 现在是这样的」以及最近的变化。

### 人设卡用在哪
- 分身：系统提示词里带她本人的人设卡。
- 助理：系统提示词里带所有核心成员的人设卡。
- `get_person` 会返回档案、关系、重要记忆和当前人设卡；分身可调用，但服务端强制只能查自己。
- 都遵守 M1 的「会话开始时冻结」规则：进行中的对话不会因为人设卡更新而改动历史，新对话才用新版。

### 分身隔离与边界
- 分身调用记忆查询和地点工具时，统一带上 `VisibleTo`，只返回「关于她本人 + 公共/地点」的记忆。
- `ask_persona` 在服务端强制只允许助理调用，且只能请老婆/妈妈分身做成人对话预演，不依赖管理端的工具勾选来保证隔离。
- 手机端分身对话始终显示「这是模拟」；女儿页明确标成育儿档案顾问，不提供假装孩子说话的预演入口。

### 预演
- 助理新增工具 `ask_persona`：拿不准对方听了会怎么想时，先把一句话交给老婆或妈妈的分身预演，再据此调整「可以这样说」。
- 手机端在老婆/妈妈分身对话里有一个「🎭 预演一句我想说的话」快捷按钮。

## 3. 新增配置

| 配置 | 默认 | 说明 |
|---|---|---|
| `storage.dir` | `../data` | 截图目录，两个服务必须指向同一个目录 |
| `worker.enabled` | `true` | 是否在这个进程里跑后台任务 |
| `extract.auto_confirm` | `0.85` | 自动整理的记忆直接生效的置信度门槛，两个服务要一致 |

新增模型路由：`persona.card`（默认 `claude-opus-5-5`，effort high）。

## 4. 验证情况
- 单元测试：结构化输出 schema 的严格性、抽取结果清洗、扩展字段、原始记录提示词、图片 + JSON 输出的请求形状、本地存储防路径穿越、人设卡提示词与格式化。
- 前端：两个应用类型检查和正式构建通过，手机尺寸下看过「整理聊天 / 截图」页面。
- **仍未在真实 MySQL 和真实 Claude API 上联调。**
